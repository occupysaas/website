Clean room. AI rebuild. Drop-in.

We do not leak, decompile or copy anyone's code. Every project is rebuilt from public documentation and open standards, with AI doing the heavy lifting on the build side of a strict firewall, then proven compatible against the vendors' own public SDKs.

Read the public record

Public API references, open standards like OAuth 2.0 and OIDC, and published SDK behaviour become a written specification. Nothing confidential, nothing leaked, nothing from former employers.

Raise the firewall

Spec writers and builders stay separated. Each repo carries a CLEAN_ROOM.md policy, and provenance is recorded for every fixture and reference.

Rebuild with AI

AI agents implement from the spec alone, contracts first (openapi.yaml), then code, then tests, under human review at every merge.

Prove compatibility

A compatibility laboratory runs the vendors' own public client SDKs against our server. If your existing code does not work unchanged, it is not done.

Release it to everyone

Apache-2.0. Self-hostable. Pluggable storage. No telemetry you did not ask for, and no seat counter.

The clean-room firewall

What crosses the line, and what never does.

Allowed in

  • Public SDK behaviour

Never allowed

  • Decompiled binaries
  • Former-employer confidential info
  • Copied UI assets or trademarks

Fair questions.

Straight answers about the method, the licence and what is ready today.

Still unsure? Ask in Discord.

Is this legal?

Clean-room reimplementation is a long-established way to build compatible software: you work only from public information and independently write your own code. Interoperating with an API is not the same as copying a product. Each project publishes its clean-room policy and source provenance so anyone can check the work. This page is not legal advice. If you are adopting a project for a business, talk to your own counsel.

Are you affiliated with Auth0, Okta or Salesforce?

No. OccupySaaS and its projects are independent and not affiliated with, endorsed by, or sponsored by any vendor named on this site. Product names are used only to describe compatibility.

Can former employees of those companies contribute?

Yes, but never with confidential knowledge from a former employer. Contributors work only from public material, and anyone with relevant inside knowledge should stay on the public-spec side of the firewall or sit that project out. When in doubt, read the project's CLEAN_ROOM.md and ask first.

Why use AI to build it?

Because the giants had thousands of engineers and we have a movement. AI agents let a small group turn a precise spec into working code quickly. Humans write the specs, review every change, and own the result, and compatibility tests against real SDKs decide what counts as done.

Why Go?

Portability. A Go project compiles to a single self-contained binary, so self-hosting means dropping one file onto a server or into a Docker or Podman image. No installer, no runtime to set up, no tree of shared libraries to keep in sync. The same toolchain cross-compiles for Linux, macOS, Windows, x86 and ARM, and the result fits in a minimal container image. If you are leaving a SaaS vendor, the replacement should be this easy to carry.

Why not Rust?

Nothing is wrong with Rust, and we are not against it. Go was picked for the first projects because it makes the one-file, container-friendly drop-in the default with very little build setup. Rust can get there too; Go just gets there more simply for the kind of servers we are building.

Rust recreations of these projects are welcome. They just have not been made yet. The specs, API contracts and compatibility tests are language-neutral, so a Rust port can be checked against the same SDKs. If you want to start one, open an issue and say which project.

Is it production-ready?

Not yet. ZeroAuthy's first release candidate, v1.0.0-rc.1, is an early preview, and its compatibility matrix lists the gaps. SalesCompel is earlier still, and its README says exactly which features work today. Try them, break them, and file issues.

What does it cost?

Nothing. Every project is released under the Apache License 2.0. Run it, fork it, sell services around it. The only thing we ask is that you contribute back what you can.
